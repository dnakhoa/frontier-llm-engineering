# Exercises — Chapter 26: What's next

Covers [Chapter 26](../book/part-5-the-job/26-whats-next.md). Solutions: [`solutions/ch26.md`](solutions/ch26.md).

Legend: 🔢 drill · 🏗️ design · 📄 paper · ★ direct · ★★ synthesis · ★★★ beyond the chapter

The last set. Two of these are calibration exercises against a chapter that says up front it will be wrong.

---

## 26.1 🏗️ ★★ Calibrate the chapter

§26.1 states that the specific techniques will look dated within two years and the constraints will not.

1. Pick three specific predictions from Chapter 26. For each, write down what you would expect to see two years from the date you are reading this if it were right, and what you would see if it were wrong.
2. Which one do you think is most likely to be wrong, and why?
3. §26.1 says the chapter is most likely to underestimate how fast boring engineering problems get solved and overestimate how fast conceptual ones do. Give an example of each pattern from the last three years.
4. Date this exercise and keep it. Revisit in two years.

---

## 26.2 🏗️ ★★★ Convert judgement into verification

§26.9 and §12.9 both argue that the strategic move is turning judgement problems into verification problems.

Pick a domain from the "no verifier" list — creative writing, explanation clarity, safety judgements, or open-ended advice.

1. State precisely what you would need to verify.
2. Design a partial verifier: a program that checks *some* necessary conditions, even if not sufficient ones.
3. What does your verifier fail to capture, and what would a policy that games it produce?
4. Would you use it as an RL objective, an inference-time ranker, or a data filter? Justify with [Exercise 16.5](ch16.md)'s distinction.
5. What would have to be true for a full verifier to exist in this domain?

## 26.3 🔢 ★★ The environment economy

§26.3 argues environments become the contested resource.

1. Using [Exercise 18.1](ch18.md)'s arithmetic, estimate the engineering cost of building 10,000 reproducible agentic task instances in a new domain.
2. Compare that against the cost of the RL run those tasks would support.
3. Why is this cost structure different from that of pre-training data?
4. What does it imply about whether environments will be shared or hoarded?
5. What would an "open environments" project need to provide to be as useful as FineWeb was for data?

## 26.4 🏗️ ★★ The ceiling question

§26.9 lists "is the base model the ceiling?" as the most important open question.

1. State both hypotheses precisely enough to be falsifiable.
2. What evidence in this book supports each?
3. Design an experiment that would distinguish them. What result would falsify each?
4. If the base model *is* the ceiling, what follows for how compute should be allocated?
5. If it is not, what follows?

---

## 26.5 🔢 ★★ Inference compute as a substitute

§26.5 notes that at some budgets, inference compute substitutes for training compute.

1. Using [Exercise 8.1](ch08.md)'s framing, write the total-cost objective including inference.
2. A model serves 10 billion queries at 500 output tokens each. Compare a 91B model at pass@1 against a 30B model at maj@8, assuming the smaller model with voting matches the larger model's accuracy.
3. Which is cheaper over the model's life, and at what query volume does the answer flip?
4. What does this imply about the compute-optimal model size for a heavily-served model?
5. Name two things this analysis ignores that would change the answer.

## 26.6 🏗️ ★★ What you would bet on

1. Of §26.8's durable list — arithmetic, memory hierarchy, communication cost, failure at scale, RL optimizes what you specify, verification beats judgement, evaluation is the bottleneck, data is the product — which would you bet against, if any?
2. Which of §26.2 through §26.7's directions would you personally work on, and why?
3. Which is most over-hyped relative to its likely impact?
4. Which is most under-invested relative to its likely impact?
5. Write the one-paragraph answer you would give to "what should I learn to still be useful in five years?"
