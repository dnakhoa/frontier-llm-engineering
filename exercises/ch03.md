## 3.1 🔢 ★ The funnel

You start with 100 PB of raw Common Crawl WARC files and need 15T tokens of training data.

Assume: text extraction keeps 15% of raw bytes; language filtering keeps 45% of that; quality filtering keeps 25% of that; deduplication removes 60% of what survives; and the surviving text averages 4.2 characters per token in UTF-8.

1. How many bytes survive each stage?
2. How many tokens do you end up with?
3. Do you have enough for a 15T-token run? If not, name three ways to close the gap and rank them by risk to model quality.
4. Which single stage would you tune first if you were 30% short, and why that one?

## 3.2 🔢 ★★ MinHash economics

You are deduplicating 10 billion documents with MinHash-LSH: 128 permutations, banded into 16 bands of 8 rows each.

1. How much memory does the signature matrix require, at 4 bytes per hash?
2. For a document pair with true Jaccard similarity $s$, the probability of being detected as a candidate is $1 - (1 - s^r)^b$ where $r = 8$ and $b = 16$. Compute it for $s = 0.5$, $0.7$, $0.8$, $0.9$.
3. Where is the effective threshold — the similarity at which detection probability crosses 50%?
4. You want to catch near-duplicates at $s = 0.7$ instead. Suggest a $(b, r)$ pair that moves the threshold there, and state what it costs.

## 3.3 🔢 ★★ Epochs, and when repetition stops paying

You have 8T unique tokens and want to train on 15T.

1. How many epochs is that?
2. The commonly cited guidance is that up to ~4 epochs of repeated data is roughly as good as fresh data, with returns degrading after. Are you inside that budget?
3. You could instead train on 8T tokens for one epoch and use the remaining compute for a larger model. Using Chinchilla's ~20 tokens/parameter, what model size does each option imply, and which would you pick for a model you intend to *serve* heavily?
4. Name two ways to get more unique tokens and the specific quality risk each carries.

## 3.4 🏗️ ★★ Design a mixture

Design the pre-training data mixture for a 30B model targeting strong code, competent math, and native-quality English, Vietnamese, and Japanese. Budget: 6T tokens.

1. A mixture table with token counts per source, summing to 6T.
2. For each source, the upsampling or downsampling factor relative to its natural abundance, and why.
3. Vietnamese and Japanese web text is far scarcer than English. How many epochs of each will you effectively run, and at what point does that become a problem?
4. Name the ablation you would run to validate the code share, and what result would make you change it.
5. Which decision in your mixture is most likely to be wrong, and how would you find out before spending the full run?

## 3.5 🏗️ ★★ Rank the filters

Below are eight filters. For each: what it removes, what it *wrongly* removes, and roughly what fraction of a web corpus it drops.

1. Language identification with a confidence threshold
2. Document-length minimum
3. Mean-words-per-line heuristic
4. Symbol-to-word ratio
5. Repeated-line fraction
6. A learned quality classifier trained on Wikipedia-vs-web
7. Toxicity classifier above a threshold
8. Benchmark n-gram decontamination

Then: which of these would you be most reluctant to run aggressively, and why? (Two of them have well-documented demographic or dialectal side effects.)

## 3.8 🔢 ★★★ The storage bill

Your pipeline processes 100 PB of raw input and produces 15T tokens of output.

1. At 4.2 characters per token, how many bytes is the final tokenized corpus stored as `uint32` token IDs?
2. Could you store it as `uint16` instead? What does that require of the tokenizer, and what does it save?
3. During the run, 2,048 GPUs read this corpus continuously at the throughput you computed in [Exercise 1.2](ch01.md). What aggregate read bandwidth does the data loader need?
4. Is that achievable from a shared network filesystem? What is the standard architecture for making it work?
