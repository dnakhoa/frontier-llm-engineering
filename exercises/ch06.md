# Exercises — Chapter 6: Distributed training

Covers [Chapter 6](../book/part-2-pretraining/06-distributed-training.md). Solutions: [`solutions/ch06.md`](solutions/ch06.md).

Legend: 🔢 drill · 🏗️ design · 📄 paper · 🧪 lab · ★ direct · ★★ synthesis · ★★★ beyond the chapter

**These are the interview questions.** Exercise 6.1 and Exercise 6.7 in particular are asked, in some form, in essentially every frontier training interview. Do them until they are boring.

---

## 6.1 🔢 ★ The memory wall

A 70B dense model, BF16 mixed precision, AdamW with FP32 master weights.

1. Bytes per parameter for weights, gradients, and optimizer state combined. Show the breakdown.
2. Total static memory in GB.
3. How many 80 GB H100s does the static state alone require?
4. Repeat for a 405B model and for DeepSeek-V3's 671B total parameters.
5. Why does the MoE case use total rather than active parameters here?

---

## 6.2 🔢 ★★ ZeRO stages

Same 70B model, on 64 GPUs with data parallelism.

1. Per-GPU static memory under plain DDP (no sharding).
2. Under ZeRO-1 (optimizer state sharded).
3. Under ZeRO-2 (optimizer state + gradients sharded).
4. Under ZeRO-3 / FSDP (everything sharded).
5. Which stage is the first that fits on an 80 GB card, ignoring activations?
6. ZeRO-3 shards parameters, so they must be all-gathered before each layer's forward. What does that cost, and under what condition is it free?

---

## 6.3 🔢 ★★ Activation memory

70B model: 80 layers, $d = 8192$, sequence length 8,192, micro-batch size 1, BF16.

1. Roughly how much activation memory does one transformer layer store for the backward pass, ignoring attention's internals? (Count the tensors a residual-stream implementation must keep.)
2. All 80 layers?
3. Compare against the static memory from §6.1. Which dominates?
4. With full activation recomputation, what does this become, and what does it cost in compute?
5. Selective recomputation [\[39\]](../book/appendix/b-references.md#39-korthikanti-2022-activation-recomputation) claims most of the saving for about a third of the cost. What is it recomputing and what is it keeping?

---

## 6.4 🔢 ★★ Communication volume

70B model, 64-way data parallelism, global batch of 4M tokens.

1. Under DDP, how many bytes are all-reduced per step?
2. Ring all-reduce moves $2(N-1)/N \times$ the payload per rank. How many bytes crosses each rank's link?
3. At 400 Gb/s InfiniBand per node, how long does that take?
4. If a step takes 8 seconds of compute, what fraction is communication? Is that acceptable?
5. Under ZeRO-3, the communication is different. What operations replace the all-reduce, and what is the total volume?

---

## 6.5 🔢 ★★ The pipeline bubble

Pipeline parallelism with $P$ stages and $M$ micro-batches.

1. Derive the bubble fraction for GPipe.
2. Compute it for $P = 8$, $M = 8$; $P = 8$, $M = 32$; $P = 16$, $M = 32$.
3. What is the rule of thumb for $M$ relative to $P$?
4. Interleaved 1F1B with $v$ model chunks per device divides the bubble by $v$. What does it cost?
5. Why can you not simply set $M$ very large?

---

## 6.6 🔢 ★★ Expert parallelism and the all-to-all

A 256-expert MoE, top-8 routing, 8-way expert parallelism (32 experts per GPU), micro-batch of 4,096 tokens, $d = 7168$, BF16.

1. How many token-copies are dispatched per layer?
2. How many bytes does the dispatch all-to-all move, per GPU?
3. The combine all-to-all moves the same volume back. Total per layer?
4. Over 58 MoE layers (V3's count: 61 layers, the first 3 dense), per micro-batch?
5. Compare against the DP all-reduce volume from §6.4. Which dominates, and what does that imply about where EP ranks should be placed? Then square your answer with DeepSeek-V3, which ran 64-way EP across 8 nodes ([fact sheet](../book/appendix/fact-sheets/deepseek-v3.md#parallelism-layout)).

## 6.7 🏗️ ★★★ Size a run

**The interview question.** You have 1,024 H100s in 128 nodes of 8, NVLink within a node, 400 Gb/s InfiniBand between nodes. Train a 200B-total / 25B-active MoE on 8T tokens at 8K context.

1. What questions would you ask before answering? (List them first — this is scored.)
2. Choose TP, PP, EP, and DP degrees. Show the memory arithmetic per GPU.
3. Choose micro-batch size, gradient accumulation, and global batch size in tokens.
4. Choose the recomputation policy.
5. Estimate MFU and wall-clock time to completion.
6. Name the three things most likely to make your estimate wrong.
7. Now the interconnect is 100 Gb/s Ethernet instead of InfiniBand. What changes?

## 6.8 🏗️ ★★ Why these degrees and not others

For each rule of thumb, explain the mechanism and name the situation where it is wrong.

1. "Keep TP within a node."
2. "Use PP only when the model does not fit with TP and ZeRO."
3. "Make DP as large as possible."
4. "EP degree should divide the expert count evenly."
5. "Micro-batch size 1 with lots of accumulation."

## 6.9 📄 ★★ Read the DeepSeek-V3 parallelism

Open the V3 technical report [\[1\]](../book/appendix/b-references.md#1-deepseek-v3) and find the infrastructure section.

1. What parallelism degrees do they use, and on how many GPUs?
2. They report using **no tensor parallelism**. Why is that possible for their architecture, and what does it buy them?
3. What does DualPipe overlap with what, and why does that matter more for MoE than for a dense model?
4. What do they say about the all-to-all, and what hardware constraint shaped it?

Run [`lab06_parallelism_memory_model`](../labs/lab06_parallelism_memory_model.py).
